# v1 notes (2026-11-27)

## What one turn does
At start: copy the folder to `~/.sih/sessions/<id>/` (`work/` and `base/`), start a
container on `work/`, commit `baseline` inside it, pause it.

For each message: forget the last plan, unpause, let the model loop (at most 30 calls),
run its tool calls in the container, pause again, then compare `work/` with `base/`.

From a real trace (`sih chat` on a two-file repository with one failing test; the
message was "the test fails, fix it"; times are seconds after the message):

| s | What happened |
|---|---|
| 3.5 | a short line of text, then `plan`: its understanding and 4 steps |
| 4.2 | `bash`: list the project |
| 5.3 | `bash`: read both files and run pytest (1 failed) |
| 7.7 | what the bug is, then `plan` again with 2 steps done |
| 8.4 | `bash`: rewrite `calc.py` and run pytest (1 passed) |
| 10.6 | `plan`: all steps done |
| 11.3 | the reply: cause, change, what was verified |
| 11.5 | after `/diff`, `/apply` and "y": `calc.py` written to the folder |

About 7 model calls (inferred from the trace, which does not record them).

## Open items
Minor, deferred from the reviews, still true.

**Sandbox runner and code calls**
- A user `__repr__` or `stdout.write` that breaks builtins again can still kill the
  interpreter; the host restarts it and variables are lost.
- User code that reaches into `json` internals or closes all file handles can break the
  reply protocol; the host treats it as a dead interpreter.
- User code that forges a well-formed reply desynchronises the stream. Accepted; fixing
  it needs request ids.
- Deleting `/tmp/*` in the background can race the runner's own capture file.
- The "characters cut" count is bytes for large files, and is wrong when there is also
  an error. The joint output and error limit could move into the runner.
- A bash command with a NUL byte or over 128 KiB fails with a misleading message.
- Killing a process group has no time limit.
- The reply line limit is fixed while the output limit is configurable (safe at 20,000).
- The runner's `shell` mode takes the command in two ways.
- If the interpreter died between calls, the result does not say the new code was not
  run.
- A "cancelled" notice can survive `close()`; an interpreter dropped for another error
  gives no notice; the code lock is not thread-safe.
- Not closing a turn's generator can pause the sandbox in the middle of the next turn.

**Copy, diff, apply**
- Outside git, a file that vanishes while the folder is listed can fail the start with
  a raw OS error (not expected on Windows).
- In git mode, dependency folders that are not ignored are copied.
- The forced removal of a copy follows links.
- Hidden-text escaping does not cover backslashes, unassigned code points or invisible
  letters.

**Host and terminal**
- The guard against running a `git` or `docker` planted in the current folder depends
  on import order and misses `PATH` entries inside the project; resolve both once.
- Ctrl+C is delayed during the first image build.
- Docker not running shows as "image build failed".
- Wording and plurals ("1 files changed").
- With piped output, non-ASCII characters in replies can print as escapes.
- Leaving after an interrupted `/reset` is silent.
- Output panels have cosmetic rough edges.
- Very long file names made by the agent can wrap so that a screen row starts with the
  harness mark.
- The "/apply" hint is still shown after the sandbox could not be paused.
- The boxed diff cannot be pasted into `git apply`.
- It runs from a source checkout only.

**Build and tests**
- The base image and pytest in it are not pinned.
- `agent` imports `finish` from `sandbox.channel`.
- Tests read private state (`chat._container`, a private LiteLLM field); one test file
  changes logger levels globally; two tool tests assert inside `finally`.
- `tests/sandbox/test_host_programs.py` mirrors no module; some test files are large.

**Behaviour to watch**
- "Ask if unclear" may make the model ask too often.
- The trace does not record model calls, tokens or cost.
- A bare `uv run pytest` makes paid calls when `.env` has a key.
